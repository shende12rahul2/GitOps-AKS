# Local test bed: k3s on a laptop

Runs the **application** and **GitOps** parts of the POC on a single-node k3s
cluster with the same Helm charts, the same images (built from the same
Dockerfiles) and the same Argo CD flow as AKS. Azure services are replaced by
local stand-ins; Terraform/Azure parts are not exercised here.

## What is the same as AKS, what is replaced

| Area | AKS | Local k3s |
|---|---|---|
| Five microservice charts (`helm/*`) | same charts | same charts + `local/values/*` |
| Images | built by CI, pushed to ACR, pinned by digest | built from the same Dockerfiles, imported into k3s, tag `local` |
| GitOps | Argo CD syncs from GitHub, self-heal, ApplicationSet | same (Argo CD chart 10.14.0, ApplicationSet, self-heal) |
| Ingress | App Gateway + AGIC (or Traefik) | k3s built-in Traefik, `http://app.localtest.me` |
| PostgreSQL | Flexible Server, Entra tokens | `postgres:17` pod, password auth (Secret) |
| DB setup | `db-bootstrap` as Entra admin | same `db-bootstrap` image, password mode |
| Migrations | Argo CD Sync hook | same |
| Redis | Azure Managed Redis, TLS, Entra | `redis:8` pod, no TLS, same `noeviction` policy and key prefixes |
| Secrets | Key Vault + CSI, workload identity | plain Kubernetes Secrets generated by `up.sh` (never in Git) |
| Shared files | Azure Files RWX across nodes | `local-path` volume (works for all pods on one node) |
| NetworkPolicy | Cilium | k3s built-in policy controller (enforced) |
| Pod Security | restricted | restricted (`apps` namespace) |
| Airflow (optional) | Celery + Managed Redis + PostgreSQL, Git-Sync over SSH | Celery + local Redis + PostgreSQL, Git-Sync over HTTPS |
| Not covered locally | Entra SSO, workload identity, Key Vault, private networking, WAF, cross-node RWX, Azure RBAC | |

## Prerequisites

- Linux laptop (or WSL2) with 8 GB RAM free (16 GB with Airflow), 4 CPUs.
- [k3s](https://docs.k3s.io/quick-start): `curl -sfL https://get.k3s.io | sh -` then
  `mkdir -p ~/.kube && sudo cp /etc/rancher/k3s/k3s.yaml ~/.kube/config && sudo chown $USER ~/.kube/config`
  (k3d or Rancher Desktop also work: `IMPORT=k3d` / `IMPORT=none`).
- `docker` (or `buildah`, no daemon needed: `BUILDER=buildah`), `helm` 3, `kubectl`, `git`, `python3`, `curl`.
- About 6 GB free disk for images (k3s keeps an uncompressed copy of each image).
- The repository pushed to GitHub (Argo CD pulls from it). For a private repo,
  a fine-grained **read-only** token: `export GITHUB_TOKEN=...` (stays in the
  cluster as an Argo CD repository secret; never commit it).

## Run

```bash
git clone https://github.com/<you>/GitOps-AKS.git && cd GitOps-AKS
git checkout <branch>                          # the branch Argo CD should follow

# 1. GitOps mode (default): build + import images, install Argo CD, register apps
aks-gitops-deployment/local/up.sh
#    or without Argo CD (charts installed directly with helm):
MODE=helm aks-gitops-deployment/local/up.sh
#    add Airflow (heavier):
WITH_AIRFLOW=1 aks-gitops-deployment/local/up.sh

# 2. Automated checks
aks-gitops-deployment/local/test.sh

# 3. Clean up
aks-gitops-deployment/local/down.sh
```

Open:

- Frontend: http://app.localtest.me (`*.localtest.me` resolves to 127.0.0.1)
- APIs: http://app.localtest.me/api/users (products, orders, notifications)
- Argo CD: http://argocd.localtest.me (user `admin`, password printed by `up.sh`)
- Airflow: `kubectl -n airflow port-forward svc/airflow-api-server 8080:8080` -> http://localhost:8080

## Verified run

`MODE=helm` was run end to end on k3s v1.34.1 (single node, images built with
buildah): **30 passed, 0 failed** (sections 1-9 below). Argo CD (section 10) and
Airflow (section 11) need images from quay.io / registry.k8s.io, which were not
reachable from that build environment; run them on the laptop.

## What `test.sh` checks

1. All five deployments, PostgreSQL, Redis ready; `db-bootstrap` completed
2. One entry point: `/` and the four `/api/*` routes through the ingress; seed data present
3. Writes without the API key are rejected (401); security headers present
4. PostgreSQL CRUD through user-service
5. Redis: cache MISS then HIT after an update, `noeviction`, namespaced keys with TTL
6. Order flow across user, product, order and notification services; the notification file
   written by notification-service is read by the frontend pod from the shared volume
7. Files and orders survive pod restarts
8. Database isolation: user-service cannot connect to `orders_db`
9. NetworkPolicy: a pod that is not an allowed caller cannot reach notification-service
10. GitOps: all Argo CD applications Synced; a manual `kubectl scale` is reverted by self-heal
11. Airflow (optional): DAGs synced from GitHub; `order_processing_pipeline` run succeeds

## GitOps exercises

```bash
# Desired state change through Git
sed -i 's/^replicaCount: 1/replicaCount: 2/' aks-gitops-deployment/local/values/global.yaml
git commit -am "local: 2 replicas" && git push       # Argo CD syncs within ~1 min
kubectl -n apps get deploy

# Rollback = revert the commit
git revert --no-edit HEAD && git push

# New application version
# edit aks-microservices-app/services/frontend/app/templates/index.html, then
aks-gitops-deployment/local/up.sh                     # rebuilds and re-imports images
kubectl -n apps rollout restart deploy/frontend       # same tag, so restart to pick it up

# DAG change (with Airflow): edit DAG_VERSION in aks-microservices-app/airflow/dags/dag_sync_canary.py,
# push, and within ~30 s:
kubectl -n airflow exec deploy/airflow-scheduler -c scheduler -- airflow dags details dag_sync_canary | grep description
```

## Troubleshooting

| Symptom | Check |
|---|---|
| `ErrImageNeverPull` / `ImagePullBackOff` for `aks-poc/*` | images not imported: `sudo k3s crictl images \| grep aks-poc`; rerun `up.sh` or set `IMPORT` |
| Argo CD `ComparisonError` / repo not accessible | branch pushed? private repo needs `GITHUB_TOKEN`; `kubectl -n argocd get applications` |
| `*-migrate` job failing | `kubectl -n data logs job/db-bootstrap`; `kubectl -n apps logs job/<svc>-migrate` |
| Pods `Pending` with `disk-pressure` taint | free disk space; k3s evicts pods and deletes images below its free-space threshold, so rerun `up.sh` afterwards |
| `app.localtest.me` not reachable | Traefik running: `kubectl -n kube-system get svc traefik`; port 80 free on the laptop |
| Airflow tasks stuck in queued | `kubectl -n airflow logs deploy/airflow-worker -c worker`; broker secret `airflow-broker-url` |
